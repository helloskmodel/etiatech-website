# ETIA 一物一码与标签系统

一套发码系统，四种物件（设备、配件耗材、灯泡、导光管），五种标签版式，一个扫码入口。
本文是设计说明与操作手册。

## 1 · 编码方案

```
  E T L 2 6 0 0 0 1 4 2 9
  │ │ │ └┬┘ └──┬──┘ └─ 校验位（Luhn mod 10）
  │ │ │  │     └────── 该类型该年度内的流水号
  │ │ │  └──────────── 发码年份
  │ │ └─────────────── 类型：E 设备 / P 配件耗材 / L 灯泡 / G 导光管
  └─┴───────────────── ETIA，扫描员一眼知道这是谁的码
```

12 位，20 mm 标签印得下，每类型每年 100 万个码够用。

**为什么校验位是数字不是字母。** 字母表会产生 `O` 和 `I`，印在标签上和 `0`、`1`
分不清；电话里念一遍更分不清。全数字加上 `E P L G` 四个不可能被误认成数字的类型字母，
就没有这个问题。校验位用 Luhn mod 10 算在九位数字上（类型折算成数字 E=1 P=2 L=3 G=4
参与运算），能查出所有单位错误和所有相邻位互换——这正是"念错一位"和"标签磨花"两种
实际错误的形状。类型字母参与运算，所以把 L 看成 G 也查得出来。

代码：`components/labels/serial.ts`（纯函数，客户端可用）。
同样的九行算法也在 `scripts/issue-serials.mjs` 里**故意重复写了一遍**：发码脚本必须
不经构建就能跑，网站必须不依赖脚本就能校验。改一处必须改另一处。

**一件一码 vs 一料号一码：**

| 类型 | 级别 | 说明 |
|---|---|---|
| E 设备 | 一件一码 | 每台机器一个码，全生命周期可追溯 |
| L 灯泡 | 一件一码 | 每支灯一个码——以旧换新靠这个 |
| G 导光管 | 一件一码 | 每根一个码 |
| P 配件耗材 | 一料号一码 | 一个料号一个码，有多少件印多少张。给一个垫圈编序列号买不到任何东西 |

## 2 · 数据来源

```
__OmniCure.xlsx  (ERP 导出的存货档案)
      │
      │  node scripts/build-sku-master.mjs <inventory.xlsx>
      ▼
data/skuMaster.json        308 个 SKU：存货编码 / 料号 / 描述 / 类别 / 产地 / 单位 / 推定类型
      │
      │  node scripts/issue-serials.mjs --sku <存货编码> [--qty N] [--batch X]
      ▼
data/serialRegistry.json   发码登记（只追加，禁止手改）
      │
      ├─→ /tools/labels?codes=…        打标签
      └─→ /scan?id=<CODE>              扫码落地页
```

存货表三个关键列名不符直觉：**存货编码**是 ETIA 自己的物料编码，**存货名称**里放的是
厂家料号，**规格型号**里放的是描述。`build-sku-master.mjs` 已按此映射。

存货表变了就重跑一次并提交结果。已发出的码按**存货编码**关联，所以 ERP 里把描述改顺
眼了不会让已经贴在箱子上的标签失效。

### 发码

```bash
# 50 支 S2000 Elite 标准灯泡，批次 EX26-07
node scripts/issue-serials.mjs --sku L02C007 --qty 50 --batch EX26-07

# 一个配件料号（一料号一码；再发会被拒绝）
node scripts/issue-serials.mjs --sku L02C085

# 查某个存货编码已发过哪些码
node scripts/issue-serials.mjs --list L02C007
```

脚本打印出可直接打开的打标签链接。

**登记表在仓库里是空的**，这是对的：里面每一行都应该对应一件真实贴过标签的东西。
第一次发码从 `000001` 开始。

## 3 · 标签版式

版式取自 ETIA Label & QR Service System 草案：顶部 ETIA-TECH 标志 + LIFECYCLE
SUPPORT 徽标，彩色标题说明这是什么，下面一行说明扫码能办什么事，然后是 ID 与
机读部分。

| 版式 | 尺寸 | 用在 | 机读 | 特有内容 |
|---|---|---|---|---|
| `equipment` | 70 × 30 mm | 设备（E） | 仅二维码 | "Do not cover factory rating or certification labels" |
| `lamp` | 70 × 30 mm | 灯泡（L） | 二维码 + 条形码 | 批次、发码日期 |
| `part` | 70 × 30 mm | 配件耗材（P） | 二维码 + 条形码 | — |
| `guide` | 70 × 30 mm | 导光管（G） | 二维码 + 条形码 | 与警示标签配对打印 |
| `guide-warning` | 35 × 30 mm | 导光管（G） | — | 红色 DO NOT BEND 四语警示 |

**为什么统一 70 × 30，而不是草案画的 50 × 25。** 这是唯一一处必须改的地方，理由是
条形码印不出来：

桌面标签机是 203 dpi，一个点 0.125 mm。Code 128 的窄条如果细于两个点，打印出来的
边缘会抖动整整一个模块，扫出来要么是错的要么扫不出。所以设计目标是**每模块
0.25 mm**，绝对下限 0.19 mm。实测各方案所需宽度：

| ID | 字符数 | 模块数 | @0.25mm 需要 | @0.19mm 需要 |
|---|---|---|---|---|
| `ETL260000017`（现行） | 12 | 165 | 41 mm | 31 mm |
| `012-68000R-1841`（草案灯泡） | 15 | 209 | 52 mm | 40 mm |
| `805-00002-L02C047`（草案导光管） | 17 | 242 | 61 mm | 46 mm |
| `ETIA-EQP-S2000-000123`（草案设备） | 21 | 264 | 66 mm | 50 mm |

草案画的 50 mm 标签上，条形码实际只有 26–35 mm，对应每模块 0.11–0.15 mm——
低于一个打印点。图上好看，机器上印不出来。

现行 12 位码在 70 mm 标签上给到 42 mm，每模块 0.25 mm，正好达标。

**为什么 ID 保留 `ETL260000017` 而不是改成 `012-68000R-1841`。**
草案的想法是让 ID 本身可读——看一眼就知道是什么料号。这个诉求成立，但**标签上已经
印了料号**（ID 下面一行就是 `012-68000R · Standard Spare 200W Lamp for S2000E`），
所以 ID 不必再承担一次。用短码换来的是：

- 条形码能在 70 mm 内印到 0.25 mm/模块（可读 ID 需要 52–66 mm）；
- 有校验位——念错一位、相邻两位写反、L 看成 G，全都当场查得出来。草案的 ID 没有
  校验位，手输一个近似值会被当成"查无此码"，而不是被纠正。

如果业主仍希望 ID 可读，代价是标签加宽到 90 mm 以上，或者接受条形码低于打印下限。
这是一个可以改的决定，但要连着标签尺寸一起改。

**草案里另外两处按业主既有指令调整：**

1. 导光管 ID 草案用的是 `805-00002-L02C047`，后半是**存货编码**。存货编码标的是
   存货表里的一行，不是其中一件——50 根导光管会共用一个 ID，一物一码就没有了。
   草案自己也给了"或流水号"的替代方案，取流水号。
2. 标题草案写 `OMNICURE LIGHT GUIDE`，改为 **`ETIA LIGHT GUIDE`**——导光管是 ETIA
   自有产品线，不是 Excelitas 目录件。灯泡标题保留 `GENUINE OMNICURE LAMP`，
   那确实是原厂件。

**贴附位置**（在 `/tools/labels` 页面上也写着，因为这半套规则活在软件之外）：

- 设备：贴在厂家铭牌**附近**，绝不覆盖铭牌。绝不覆盖 CE / UKCA / ETL 标志、序列号、
  额定值或任何安全文字——覆盖这些不是美观问题，是涂改法定安全信息。
- 灯泡：贴在灯泡盒上，不覆盖含汞警示贴纸与料号。
- 导光管：两张贴在同一张底纸上，贴在接头端附近——人拿导光管时手会碰到的位置。
- 配件：贴在袋子或盒子上，不覆盖厂家自己的料号标签。

**关于颜色。** 版式用了绿/蓝/红三色（品牌绿、类别蓝、警示红）。彩色标签需要彩色标签机
或预印底纸；全黑打印时版面依然成立，只是失去类别区分。红色警示标签建议用预印红底纸，
不要指望热敏机打出那片红。

**标志是占位的。** `Wordmark` 组件里的 ETIA-TECH 是我按图临摹的 SVG，正式开印前
换成品牌方的矢量文件。

### 导光管警示标签

导光管是 ETIA 自有产品，这张标签是 ETIA 自己的产品安全责任，不是转述厂家警告。

**标签上不印最小弯曲半径数字，而且以后也不印。** 2026-09-12 业主给出结论：
**导光管不能弯曲**——不存在"最小弯曲半径"这个数，因此没有数可印。标签印的是
绝对规则：DO NOT BEND / 严禁弯折 / ห้ามดัด / KHÔNG UỐN，加上 FRAGILE LIGHT GUIDE
与 DO NOT PULL / CRUSH。`/consumables` 与扫码页的文案已按同一口径改写：不给
"大弧度走线"这类留有余地的说法，因为那等于暗示存在一个可以照着弯的限度。

导光管也**不标使用寿命**——同样是因为 ETIA 未给出，`/consumables` 上导光管那一块
没有寿命栏。

### 打标签

```
/tools/labels?codes=ETL260000017,ETL260000025[&template=lamp][&copies=3]
```

- 内部页面，`noindex`，不在导航里，不在 sitemap 里。
- 无客户端 JavaScript：控件是 GET 表单，打印按钮是浏览器自己的。仓库电脑装什么浏览
  器都能用。
- 只能打已发出的码。没发过的码会被列成问题项而不是被打出来——这是"统一发码"的意义。
- **打印必须 100%**，不要"缩放以适应页面"。尺寸是毫米，缩 6% 就对不上模切纸，
  而且要等一整卷跑完才有人发现。

## 4 · 扫码落地页 `/scan?id=<CODE>`

四语（跟站点语言 cookie），按类型分支：

- **全部**：编码、类别、批次、登记日期 + "订购替换件" / "咨询 ETIA"
- **设备**：这台机器能装的灯泡料号，可直接加入询单（见 §3 设备标签）
- **灯泡**：以旧换新入口
- **导光管**：弯折警示（与标签同一句话）
- **未发出的码**：明确告诉对方"格式对，但我们没有发过它"，并请对方拍照发来。
  拿着一张不是我们印的标签的客户，需要被明确告知这一点，而不是看到一个报错页。

**不显示产地。** 存货表的"产地"列记的是 ETIA 从哪里采购，不是原产地申报，而且两者
会对不上：012-64000R 存货表写加拿大，灯泡盒上盖的是 MADE IN USA。原产地属于商业
发票的内容，不该出现在客户拿着盒子对照的页面上。

`noindex`：这些页面是给手里拿着东西的人看的，数量多、内容薄，进搜索索引就是
doorway page。

所有标签的二维码都指向**同一个入口** `www.etiatech.com/scan?id=<CODE>`（草案 §4 的
要求），由页面自己判断这个码是设备、灯泡、导光管还是配件，再显示对应内容。没有按
产品类型各开一条路由：标签印出去之后要在设备上待很多年，而站点结构会改。
`/s/<CODE>` 作为短别名保留——条形码扫出来或电话里念出来的码，斜杠后面比问号后面
好输入。两条路由走同一个 `scanResult.ts`，不会各自漂移。

URL 形状**已冻结**。`components/labels/serial.ts` 的 `SCAN_BASE` 是唯一书写处。

二维码里只放 ID，不放任何客户信息（草案 §7 同一要求）。

关于 `LAMP.ETIATECH.COM`：如果要用这个短域名，做成 301 到 `www.etiatech.com/scan?id=…`
即可，不要做成第二套页面。已经印出去的二维码指向 `www`，两套页面意味着两套真相。

## 5 · 以旧换新

页面上给出的口径，理由在这里记一笔：

**汞灯是危险废物，不做跨境退运。** 《巴塞尔公约》与各国危废进口管制之下，把含汞灯泡
从泰国、越南寄回香港或中国，大概率是不允许的，而且这个风险由承运的一方承担。所以
落地页要求客户告知灯在哪个国家，由 ETIA 就地安排合规处置，凭登记给抵扣——
**抵扣凭的是登记与合规处置证明，不是把灯寄回来**。

**保修与以旧换新分开。** 保修是厂家对灯泡的 2,000 小时保证，条件是预热不被中断；
以旧换新是 ETIA 的商务政策。两件事混在一起，客户会拿以旧换新来主张保修。

## 6 · 验证

| 项目 | 做法 | 结果 |
|---|---|---|
| Code 128 编码 | `node --experimental-strip-types scripts/check-code128.mjs`——用按标准另写的解码器把自己的输出读回来，校验模 103 校验位与子集切换 | 53 例全通过 |
| Code 128 交叉核对 | 与 python-barcode 0.16.1 逐条比对 138 个字符串 | 136 例完全一致；2 例含数字对 `99` 的不一致，符号级解码显示对方丢了一对数字，我方正确 |
| 二维码 | 以 8 倍像素渲染四张标签上的二维码，用 OpenCV 解码 | 四张全部解回 `https://www.etiatech.com/scan?id=<CODE>` |
| 校验位 | `parseSerial` 对改一位、换相邻两位、L↔G 混淆全部拒绝 | 通过 |
| 重复发码 | 对 P 类型二次发码 | 按设计拒绝并回显已有码 |
| 页面 | `/tools/labels`、`/scan?id=<CODE>` 与别名 `/s/<CODE>`（有效 / 未发出 / 非法）、四语渲染 | 全部 200，渲染核对 |

## 7 · 还没做的

草案 §2、§3、§5、§6 的出入库流程、状态机与后台，都需要一个**能写**的后端。现在的
登记表是仓库里的一个 JSON 文件，只回答"这个码发过没有"，不回答"这个码出库给了谁"。

草案给出的状态机与字段先记在这里，等后端选型定了直接用：

- **状态**：Draft / Printed / In Stock / Reserved / Shipped / Registered /
  Calibration Due / PM Due / Service Requested / Replacement Quoted /
  Trade-in Approved / Refurbished / Replaced / Recycled / Void
- **字段**：unique_id, item_type, part_no, stock_code, lot_no, serial_no, model,
  brand, condition, language, country, status, supplier, received_date,
  warehouse_location, customer_name, shipped_date, service_case_id,
  calibration_due_date, pm_due_date, replacement_id, refurbished_date,
  recycled_date

待办：

- **内部出入库日志**：入库发码、出库扫码各写一条记录。薄记录层放在 ERP 之外
  （ETIA 内部用**企业微信**，2026-09-12 确认）。因此这一层落在企业微信上：
  群机器人 webhook 推通知，自建应用的 OAuth 直接拿员工身份，后台不再自己做一套
  账号密码。员工不会每天去开一个新网站，通知必须落到他们已经在用的工具里。
- **客户端登入**：客户自助查自己买过什么、下单、提以旧换新。落地页现在走的是邮件。
- **翻新机标注**：草案 §5 要求翻新转售的设备在站内与内部记录里明确标为
  ETIA Refurbished / Pre-owned，带翻新日期、测试结果、保修条款与服务履历，不得当新机
  呈现。存货表里确实有二手机（L01E003P2），所以这条是真实需求，等后端一起做。
- **试印 50 张**（草案 §8）：10 设备 / 20 灯泡 / 20 导光管。要测的是打印尺寸、扫码
  距离、仓库扫码枪、手机语言切换，以及走通一次完整的以旧换新。这一步**必须在批量
  开印前做**，尤其是条形码的实际扫读——上面那张模块宽度表是算出来的，不是在这台
  打印机上量出来的。
