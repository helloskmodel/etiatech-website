# ETIA 一物一码与标签系统

一套发码系统，四种物件（设备、配件耗材、灯泡、导光管），三种标签，一个扫码落地页。
本文是设计说明与操作手册。

## 1 · 编码方案

```
  E T L 2 6 0 0 0 1 4 2 9
  │ │ │ └┬┘ └──┬──┘ └─ 校验位（Luhn mod 10）
  │ │ │  │     └────── 该类型该年度内的流水号
  │ │ │  └──────────── 发码年份
  │ │ └─────────────── 类型：E 设备 / P 配件耗材 / L 灯泡 / G 导光管
  └─┴───────────────── ETIA，扫描员一眼知道这是谁的码
```

12 位，20 mm 标签印得下，每类型每年 100 万个码够用。

**为什么校验位是数字不是字母。** 字母表会产生 `O` 和 `I`，印在标签上和 `0`、`1`
分不清；电话里念一遍更分不清。全数字加上 `E P L G` 四个不可能被误认成数字的类型字母，
就没有这个问题。校验位用 Luhn mod 10 算在九位数字上（类型折算成数字 E=1 P=2 L=3 G=4
参与运算），能查出所有单位错误和所有相邻位互换——这正是"念错一位"和"标签磨花"两种
实际错误的形状。类型字母参与运算，所以把 L 看成 G 也查得出来。

代码：`components/labels/serial.ts`（纯函数，客户端可用）。
同样的九行算法也在 `scripts/issue-serials.mjs` 里**故意重复写了一遍**：发码脚本必须
不经构建就能跑，网站必须不依赖脚本就能校验。改一处必须改另一处。

**一件一码 vs 一料号一码：**

| 类型 | 级别 | 说明 |
|---|---|---|
| E 设备 | 一件一码 | 每台机器一个码，全生命周期可追溯 |
| L 灯泡 | 一件一码 | 每支灯一个码——以旧换新靠这个 |
| G 导光管 | 一件一码 | 每根一个码 |
| P 配件耗材 | 一料号一码 | 一个料号一个码，有多少件印多少张。给一个垫圈编序列号买不到任何东西 |

## 2 · 数据来源

```
__OmniCure.xlsx  (ERP 导出的存货档案)
      │
      │  node scripts/build-sku-master.mjs <inventory.xlsx>
      ▼
data/skuMaster.json        308 个 SKU：存货编码 / 料号 / 描述 / 类别 / 产地 / 单位 / 推定类型
      │
      │  node scripts/issue-serials.mjs --sku <存货编码> [--qty N] [--batch X]
      ▼
data/serialRegistry.json   发码登记（只追加，禁止手改）
      │
      ├─→ /tools/labels?codes=…        打标签
      └─→ /s/<CODE>                    扫码落地页
```

存货表三个关键列名不符直觉：**存货编码**是 ETIA 自己的物料编码，**存货名称**里放的是
厂家料号，**规格型号**里放的是描述。`build-sku-master.mjs` 已按此映射。

存货表变了就重跑一次并提交结果。已发出的码按**存货编码**关联，所以 ERP 里把描述改顺
眼了不会让已经贴在箱子上的标签失效。

### 发码

```bash
# 50 支 S2000 Elite 标准灯泡，批次 EX26-07
node scripts/issue-serials.mjs --sku L02C007 --qty 50 --batch EX26-07

# 一个配件料号（一料号一码；再发会被拒绝）
node scripts/issue-serials.mjs --sku L02C085

# 查某个存货编码已发过哪些码
node scripts/issue-serials.mjs --list L02C007
```

脚本打印出可直接打开的打标签链接。

**登记表在仓库里是空的**，这是对的：里面每一行都应该对应一件真实贴过标签的东西。
第一次发码从 `000001` 开始。

## 3 · 三种标签

三种标签都同时带**文字、Code 128 条形码、二维码**，三者内容是同一个码。
三样都要，因为三样各自解决另外两样解决不了的场合：仓库扫码枪读条形码，
手机读二维码，标签磨花了人念文字。

| 版式 | 尺寸 | 用在 | 特有内容 |
|---|---|---|---|
| `asset` | 50 × 25 mm | 设备（E）、配件耗材（P） | ETIA 服务联系方式 |
| `lamp` | 50 × 30 mm | 灯泡（L） | 批次、发码日期、"扫码登记 · 以旧换新" |
| `guide` | 70 × 25 mm | 导光管（G） | 警示三角 + 四语"严禁弯折" |

二维码里只有一样东西：`https://www.etiatech.com/s/<CODE>`。
物件的任何信息都**不**编进二维码——那会冻结在打印那一天，而标签比除了它自己的编码
以外的任何事实都活得久。纠错等级 M（约 15%），配合印出来的文字够用；Q/H 会把码点数
推高到 12 mm 见方印不清。

### 导光管警示标签

导光管是 ETIA 自有产品，这张标签是 ETIA 自己的产品安全责任，不是转述厂家警告。

**标签上不印最小弯曲半径数字。** ETIA 尚未给出该数值，而为了标签好看编一个数字比
不写更危险。现在印的是绝对规则："严禁弯折・打死弯"。ETIA 给出半径后，
`components/labels/Label.tsx` 的 `GuideLabel` 和 `ScanResultView` 各加一行即可。

导光管也**不标使用寿命**——同样是因为 ETIA 未给出，`/consumables` 上导光管那一块
没有寿命栏。

### 打标签

```
/tools/labels?codes=ETL260000017,ETL260000025[&template=lamp][&copies=3]
```

- 内部页面，`noindex`，不在导航里，不在 sitemap 里。
- 无客户端 JavaScript：控件是 GET 表单，打印按钮是浏览器自己的。仓库电脑装什么浏览
  器都能用。
- 只能打已发出的码。没发过的码会被列成问题项而不是被打出来——这是"统一发码"的意义。
- **打印必须 100%**，不要"缩放以适应页面"。尺寸是毫米，缩 6% 就对不上模切纸，
  而且要等一整卷跑完才有人发现。

## 4 · 扫码落地页 `/s/<CODE>`

四语（跟站点语言 cookie），按类型分支：

- **全部**：编码、类别、批次、登记日期、产地 + "订购替换件" / "咨询 ETIA"
- **灯泡**：以旧换新入口
- **导光管**：弯折警示（与标签同一句话）
- **未发出的码**：明确告诉对方"格式对，但我们没有发过它"，并请对方拍照发来。
  拿着一张不是我们印的标签的客户，需要被明确告知这一点，而不是看到一个报错页。

`noindex`：这些页面是给手里拿着东西的人看的，数量多、内容薄，进搜索索引就是
doorway page。

URL 形状**已冻结**——它印在会在设备上待很多年的标签上。
`components/labels/serial.ts` 的 `SCAN_BASE` 是唯一书写处。

关于 `LAMP.ETIATECH.COM`：如果要用这个短域名，做成 301 到 `www.etiatech.com/s/…`
即可，不要做成第二套页面。已经印出去的二维码指向 `www`，两套页面意味着两套真相。

## 5 · 以旧换新

页面上给出的口径，理由在这里记一笔：

**汞灯是危险废物，不做跨境退运。** 《巴塞尔公约》与各国危废进口管制之下，把含汞灯泡
从泰国、越南寄回香港或中国，大概率是不允许的，而且这个风险由承运的一方承担。所以
落地页要求客户告知灯在哪个国家，由 ETIA 就地安排合规处置，凭登记给抵扣——
**抵扣凭的是登记与合规处置证明，不是把灯寄回来**。

**保修与以旧换新分开。** 保修是厂家对灯泡的 2,000 小时保证，条件是预热不被中断；
以旧换新是 ETIA 的商务政策。两件事混在一起，客户会拿以旧换新来主张保修。

## 6 · 验证

| 项目 | 做法 | 结果 |
|---|---|---|
| Code 128 编码 | `node --experimental-strip-types scripts/check-code128.mjs`——用按标准另写的解码器把自己的输出读回来，校验模 103 校验位与子集切换 | 53 例全通过 |
| Code 128 交叉核对 | 与 python-barcode 0.16.1 逐条比对 138 个字符串 | 136 例完全一致；2 例含数字对 `99` 的不一致，符号级解码显示对方丢了一对数字，我方正确 |
| 二维码 | 以 6 倍像素渲染四张标签上的二维码，用 OpenCV 解码 | 四张全部解回 `https://www.etiatech.com/s/<CODE>` |
| 校验位 | `parseSerial` 对改一位、换相邻两位、L↔G 混淆全部拒绝 | 通过 |
| 重复发码 | 对 P 类型二次发码 | 按设计拒绝并回显已有码 |
| 页面 | `/tools/labels`、`/s/<CODE>`（有效 / 未发出 / 非法）、四语渲染 | 全部 200，渲染核对 |

## 7 · 还没做的

  出库扫码要写一条记录，这需要一个能写的后端——ERP 之外的一层薄记录层
  （飞书多维表格 / 钉钉 / 企业微信，若 ETIA 已在用其一；否则 Supabase 新加坡区 +
  一个 PWA 扫码页）。等 ETIA 确认在用什么协作工具。
- **客户端登入**：客户自助查自己买过什么、下单、提以旧换新。落地页现在走的是邮件。
- **导光管最小弯曲半径**：等 ETIA 给数。
